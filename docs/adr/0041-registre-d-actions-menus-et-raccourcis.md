# ADR-0041 — A single action registry feeds menus, shortcuts and palette

**Status:** proposed · **Date:** 2026-09-25

**Clarifies:** [ADR-0029](0029-interface-tauri-shadcn.md), on two points: how
a trigger other than a button reaches the IPC bridge, and what the native
window does when Oxyn says nothing. ADR-0029's table cited TanStack Hotkeys
among the front end's building blocks: it stops being the path for application
shortcuts (point 3).

**Clarifies:** [ADR-0038](0038-un-plantage-s-annonce-une-fois.md), on the shape
of its macOS menu: the copy of Tauri's default menu where only Quit changes
(`application_menu`, `crates/oxyn-desktop/src/commands/recovery.rs`) becomes
the bar built from the manifest (point 4). Oxyn's Quit, its shortcut and its
handling in Rust by the orderly shutdown do not change.

## Context

Oxyn must offer the interactions of a desktop application — menu bar, right
click, shortcuts, palette — to an audience coming from DBeaver, SSMS or
DataGrip. **What they do** is set by [UX-SPEC](../UX-SPEC.md), section "Menus,
shortcuts and gestures" and its subsections "Menu bar", "Context menus",
"Keyboard", "Mouse and dragging", "What Oxyn does not do, because it is not a
browser". This ADR sets **how** they are built, and what they must never
become: a second execution path ([I-01](../../CLAUDE.md#i-01)).

### What exists on 2026-09-25

Shortcuts are declared by **four mechanisms, in 27 files**, with no place
where a conflict would show:

Paths relative to `apps/desktop/src/`. Two defects can already be read in this
code: `result-grid.tsx` tests `event.metaKey || event.ctrlKey`, so `⌃C` also
copies on macOS; `sidebar.tsx` compares `event.key` to a Latin letter, which
fails on a Cyrillic layout. And two Oxyn shortcuts fall on CodeMirror default
bindings: `@codemirror/commands` 6.11.0 (installed as a transitive dependency
of `@uiw/react-codemirror`) binds `Mod-/` to `toggleComment`, and
`@codemirror/search` binds `Mod-f` to its search panel. Finally, on macOS,
`⌘W` is bound twice: by `workspace-screen.tsx`, which closes the active tab,
and by the predefined `Close Window` item that ADR-0038's menu keeps in `File`
and in `Window` (`muda`'s `⌘W` accelerator, below). If it is the menu that
receives the keystroke (point to check no. 1), `performClose:` produces a
`CloseRequested`, which `on_run_event` turns into an orderly shutdown: `⌘W`
quits Oxyn.

A single context menu exists, that of the catalog tree
(`components/oxyn/catalog-tree.tsx`, shadcn `context-menu` on Base UI), which
copies a name **quoted by the backend** (`qualified_name` of

installed in `components/ui/` and used nowhere; `command` only serves the
driver choice (`components/oxyn/driver-choices.tsx`); `kbd` already displays
shortcuts in fifteen files, each written by hand next to the binding it
describes.

### What the native window does by default

Checked on 2026-09-25 in the source of the `Cargo.lock` versions: `tauri`
2.11.5, `tauri-utils` 2.9.3, `tauri-runtime-wry` 2.11.4, `wry` 0.55.1, `muda`
0.19.3 ([I-12](../../CLAUDE.md#i-12)).

1. **On macOS, Tauri installs a menu when not given one.** `Builder::build`
   (`src/app.rs`) sets `Menu::default` if no menu is provided and
   `enable_macos_default_menu` is `true`, which is the default. This menu
   contains an application menu (About, Services, Hide, Hide Others, Quit),
   `File` (Close Window), `Edit` (Undo, Redo, Cut, Copy, Paste, Select All),
   `View` (Fullscreen), `Window` (Minimize, Maximize, Close Window) and `Help`
   (`src/menu/menu.rs`). On Windows and Linux, no menu is set. Since
   [ADR-0038](0038-un-plantage-s-annonce-une-fois.md),
   `crates/oxyn-desktop/src/main.rs` provides on macOS
   `commands::recovery::application_menu`: `Menu::default`, whose application
   menu is rebuilt identically except its last item, a `MenuItem` with
   identifier `oxyn-quit` (`CmdOrCtrl+Q`) that `on_run_event` handles by
   launching the orderly shutdown. Everything else — `Close Window` included —
   is Tauri's.
2. **The `Edit` entries are system roles.** `muda` binds them to the AppKit
   selectors `copy:`, `paste:`, `cut:`, `selectAll:`, `undo:`, `redo:`, sent
   into the responder chain; predefined `Quit` is `terminate:`, `Close Window`
   is `performClose:` (`src/platform_impl/macos/mod.rs`). Their default
   accelerators are in `src/items/predefined.rs`: `⌘W` for `Close Window` on
   macOS (`Alt+F4` elsewhere), `⌘Q` for `Quit`, `⌘H` for `Hide`, `⌘⌥H` for
   `Hide Others`. `terminate:` cannot be held back: tao does not handle
   `applicationShouldTerminate:`, and the exit arrives as `RunEvent::Exit`
   without `ExitRequested` — which is what led to writing
   [ADR-0038](0038-un-plantage-s-annonce-une-fois.md) for ⌘Q and
   [ADR-0040](0040-inscrire-la-fermeture-d-une-sortie-forcee.md) for the Dock's
   Quit and session logout ([RESEARCH-NOTES](../RESEARCH-NOTES.md#tauri-interface-and-front-end)).
3. **A menu item has no tooltip, and its shortcut is a binding.** `muda`
   0.19.3 exposes `set_text`, `set_enabled` and `set_accelerator` on an item;
   no occurrence of *tooltip* in the crate. A displayed shortcut is a captured
   shortcut: there is no display-only.
4. **Receiving an event from Rust through `listen` requires a permission.**
   `tauri` 2.11.5 files `event` among its core permissions, like `menu`.
   `capabilities/main.json` grants only three permissions, and its description
   names `event` and `menu` among what the default set would add. Oxyn's
   commands and `Channel`s are not subject to it (same description): the
   streams already go through them (`subscribe_events`,
   `commands/subscriptions.rs`).
5. **`titleBarStyle` only applies to macOS** ("The style of the macOS title
   bar", `tauri-utils` `config.rs`). On Windows and Linux, the window keeps
   the system title bar; Oxyn's header is the first row of the page, below it.
6. **Page zoom is off by default, not the rest.** `zoomHotkeysEnabled` is
   `false`: on Windows it drives WebView2's `IsZoomControlEnabled`, on macOS
   and Linux no polyfill is injected. `wry` sets
   `back_forward_navigation_gestures` to `false` and `tauri-runtime-wry` does
   not change it. On the other hand, `wry`'s `with_browser_accelerator_keys`
   (true by default: WebView2's `Ctrl+R`, `F5`, `Ctrl+P`, `Ctrl+F`) is not
   exposed by `tauri-runtime-wry` 2.11.4. `allowLinkPreview` is `true` by
   default on macOS.
7. **The system's file drop excludes HTML5 dragging on Windows.**
   `dragDropEnabled` is `true` by default, and its documentation says:
   "Disabling it is required to use HTML5 drag and drop on the frontend on
   Windows".

## Decision

### 1. An action registry, in two parts

**Every interface action has a unique identity**, declared in
`apps/desktop/src/lib/actions/`:

- **the manifest**, `actions.json` — the static part: `id`, label (and its
  per-zone variants, see 2), zone, shortcut per platform (`mac`, `other`),
  place in the menu bar (menu, group, order, mnemonic), `destructive` flag,
  `check` flag — a choice the bar ticks, like `View ▸ Theme ▸ Dark`. A menu
  can carry a `parent`: it is then a submenu, placed in that menu like an
  action, on a single level. Nothing executable;
- **the behaviors**, `registry.ts` — for each `id`, `enabled(context)`, which
  returns `true`, a reason, or absence (the absence cases are those UX-SPEC
  already sets), and `run(context)`.

```ts
type ActionBehaviour = {
  enabled: (context: ActionContext) => true | { reason: string } | "absent"
  run: (context: ActionContext) => void | Promise<void>
}
```

`ActionContext` carries the focus zone, the active tab, the selection, the
target of a context menu, and the active connection (environment,
capabilities, read-only). It is recomputed on a change of focus, tab,
selection or execution state — not on every keystroke — and compared to the
previous one: nothing goes to the triggers if it has not changed.

The identifier is a stable namespace, `<domain>.<verb>` (`console.run`,
`tab.close`, `app.quit`). The `plugin.` prefix is reserved: a plugin action
([ADR-0005](0005-wasm-plugins.md)) will be **declarative** — it will name a
`Command` —, never a front-end function, because a WASM component does not
provide one ([PLUGIN-CONTRACT](../PLUGIN-CONTRACT.md), point 1).

**Triggers only read the registry**: menu bar, context menus, keyboard,
palette, shortcut sheet — **and the buttons** that carry a registry action,
which invoke it by its `id` instead of keeping their own greying condition.
That is what guarantees `Run` is greyed out "in the same cases as its button"
(UX-SPEC, "Menu bar"): there is only one condition.

**`invoke(id, source)` re-evaluates `enabled` at call time.** A menu's
greying is only a display: an activation arriving after a context change is
ignored, with a trace, never executed on a stale state.

**Two tests hold the registry**, in `make front`: every `id` of the manifest
has a behavior and vice versa; and the conflict rules of points 2 and 3 are
checked on the whole manifest. A shortcut conflict never shows at runtime —
one of the two actions simply does not fire.

### 2. A shortcut resolves by focus zone

Zones are named in the DOM (`data-action-zone`: `editor`, `grid`, `tree`,
`tabs`, `assistant`…), and the active zone is the closest ancestor of
`document.activeElement`. An open modal dialog is a zone that masks all the
others, as `workspace-screen.tsx` already does ("Dialogs own the keyboard
while open").

- **A shortcut is unique per zone**: never two actions for the same
  combination in the same zone.
- **A more specific zone wins over the global level.** `⌘/` comments the line
  in `editor` and opens the shortcut sheet elsewhere; `⌘F` is a single action,
  `edit.find`, which searches in the zone that has focus.
- **The menu follows the active zone.** An item whose combination is masked by
  a more specific zone displays without it; the one that carries it in the
  active zone displays it; a label that depends on the zone takes the variant
  declared in the manifest for it.
- **Between tabs: `⌃Tab` and `⌃⇧Tab` only.** No `⌘1…9`: `⌘1` shows the
  catalog and `⌘2` gives focus to the preview grid (`workspace-screen.tsx`;
  UX-SPEC, "Keyboard").
- **Keys internal to a component are not actions.** Arrows, `Home`/`End`,
  `PageUp`/`PageDown`, `Enter` and `Esc` that move focus or close a surface
  belong to the component's ARIA pattern and stay in its `onKeyDown`. The
  criterion: a key that has a menu or palette entry is an action; a key that
  navigates within a widget is not. The shortcut sheet lists them anyway,
  declared in the manifest as belonging to their zone.
- **The CodeMirror keymap no longer binds a combination the manifest knows.**
  `sql-editor.tsx` builds its Oxyn bindings from the registry, and removes from
  the default bindings those the manifest declares for the `editor` zone
  (`Mod-/`, `Mod-f`): they go through the registry, which calls the
  corresponding CodeMirror command. A combination bound in two places fires
  twice, or once depending on delivery order — in both cases without an
  error.

### 3. The keyboard: one dispatcher, written matching rules

**A single `keydown` listener**, in the capture phase on `window`, set by
`lib/actions/keyboard.ts`. The uses of `useHotkeys`, the window `keydown`
listeners and the `⌘B` of `sidebar.tsx` migrate to it; the latter, generated
by shadcn and not edited by hand, is disabled through its provider or declared
in the manifest as belonging to the component, so that the sheet shows it and
the conflict test sees it. The dispatcher is written by Oxyn rather than
delegated to `@tanstack/react-hotkeys`: the rules below are ours, and the
library declares itself alpha.

- **`Mod` is `metaKey` on macOS and `ctrlKey` elsewhere — never one or the
  other.**
- **A key's identity**: `event.key` when it is a single printable ASCII
  character; otherwise the letter or digit derived from `event.code`
  (`KeyC` → `c`). This covers `⌥` on macOS, which changes the character
  produced, and non-Latin layouts. **Digits are always read through
  `event.code`**: on AZERTY, they require `⇧`.
- **`⇧` is not compared for punctuation**, since it is used to produce it
  (`/` is `⇧:` on AZERTY). Consequently, **no action declares
  `Mod+Shift+<punctuation>`**; the manifest test refuses it.
- **On Windows and Linux, no action declares `Ctrl+Alt+<printable key>`**:
  `AltGr` is reported there as `Ctrl+Alt`, and the combination steals a
  character (on French AZERTY, `AltGr+0` produces `@`).
- **A keystroke being composed (`event.isComposing`) is never a shortcut**: a
  CJK input method validates with `Enter`.
- **`⇧F10` and the `Menu` key** are the `context-menu.open` action: it emits
  `contextmenu` on the focused element, which its zone's menu handles as a
  right click — which is what the catalog tree already does on the focused
  row.
- **A destructive action (`destructive: true`) has no shortcut.** A shortcut
  makes reflexive what ADR-0042's review exists to slow down.

### 4. macOS: native menu bar, described by the manifest

`crates/oxyn-desktop/src/menu.rs` builds the bar with `tauri::menu` at
startup, **from the manifest**, read through `include_str!` and parsed by
`serde` — a Rust test parses it and builds the menu description, so that an
invalid manifest fails in CI and not at launch. The bar therefore exists
before the webview has loaded, and its labels never come from JavaScript.

It replaces ADR-0038's `application_menu`, hence the copy of `Menu::default`,
and explicitly takes over what belongs to the system, as `muda` predefined
items: About, Services, Hide, Hide Others, Show All, Fullscreen, Minimize,
Zoom, and **Cut, Copy, Paste, Select All** — the roles that reach a webview
text field ("Context", point 2). **Three roles are not taken over as
predefined**:

- **Quit** stays ADR-0038's item: the manifest's `app.quit` action, `⌘Q`,
  whose native item carries the identifier `on_run_event` recognizes (today
  `oxyn-quit`). **It is the only entry Rust executes itself**, without a round
  trip through the webview: the orderly shutdown flushes the webview's drafts,
  and a frozen webview must not prevent quitting. The item calls the same
  function as `request_exit` (point 5): resolution of open transactions
  (ADR-0043), then orderly shutdown. The predefined `terminate:` cannot be
  held back ("Context", point 2);
- predefined **Close Window** carries `⌘W`, which Oxyn gives to `tab.close`;
  closing the window is a registry action, without `⌘W`. This removal closes
  the double binding noted in "Context";
- **Undo** and **Redo**: UX-SPEC gives them a scope that goes beyond text (the
  layout). They are registry actions if point to check no. 3 confirms that an
  action can undo the editing of a native field; otherwise they stay
  predefined, limited to text, and the layout has its own entry.

**Outbound.** A click, or a shortcut captured by the bar, arrives as
`RunEvent::MenuEvent`, where `on_run_event` already handles ADR-0038's Quit.
Apart from `app.quit`, `menu.rs` checks that the `id` belongs to the manifest
and sends it to the active window through a `Channel` opened by the
`subscribe_menu` command (`commands/menu.rs`, same replacement model as
`commands/subscriptions.rs`). No `emit`: `listen` would require a
`core:event` permission ("Context", point 4). The message carries **only an
`id`**, validated by a `zod` schema on entry
([ADR-0031](0031-validation-des-reponses-ipc.md), point 5), then
`invoke(id, "menu")`. **`menu.rs` builds no `Command`**: it does not know what
the action does.

**Return.** The `set_menu_state` command receives, for each manifest item
present in the bar: enabled or not, label variant index, shortcut shown or
not, and `checked` (`Option<bool>`), the tick of a `check` item, ignored on
any other item. It accepts neither free text nor an arbitrary combination —
an XSS cannot rename "Quit" or bind a key —, and an unknown `id` is a
non-retryable error. It is synchronous, hence on the main thread: it only
makes `set_enabled`, `set_text`, `set_accelerator` calls there, without I/O
([I-05](../../CLAUDE.md#i-05)). The front end only calls it on a context
change (point 1).

**On macOS, a combination has a single binding**: if it is carried by a
native item in the active zone, the dispatcher of point 3 ignores it, and
`set_menu_state` moves the accelerator when the zone changes (`⌘/` moves from
`Keyboard shortcuts` to `Toggle comment` when the editor takes focus). This
rule makes the delivery-order question (point to check no. 1) irrelevant for
combinations with `⌘`.

**`Esc` is never a native accelerator.** `Query ▸ Cancel` would capture `Esc`
everywhere — closing a dialog, an editor completion, a menu —, and `muda`
offers no display without a binding ("Context", point 3). The native `Cancel`
entry therefore displays **without a shortcut** on macOS; `Esc` stays handled
by the console's zone, as today (`sql-editor.tsx`, console bar), and appears
in the palette and the shortcut sheet. `⌘.` is not used.

The native bar targets the active window: distribution across several
windows — one `Channel` per window, the state pushed by the one that takes
focus — falls under ADR-0043.

**The Dock menu stays the system's.** This ADR adds no entry to it. Its
`Quit`, like the macOS session logout, sends `terminate:`: this path does not
go through the registry, cannot be held back, and records the closing as
[ADR-0040](0040-inscrire-la-fermeture-d-une-sortie-forcee.md) decides, drafts
not flushed.

### 5. Windows and Linux: web menu bar

The bar is the shadcn `menubar` component, in the first row of the page —
under the system title bar, which `titleBarStyle` does not remove ("Context",
point 5). It reads the same manifest. `Alt` reveals the mnemonics, `F10` gives
it focus; below 1200 px, it folds into a single menu button (UX-SPEC,
"Reduced width"). It also displays the shortcuts a zone holds, `Esc`
included: here, displaying is not binding.

No native menu is set on these platforms: it is already Tauri's behavior
without a menu, and `application_menu` is only built on macOS ("Context",
point 1).

**`File ▸ Exit`** — settled by the user on 2026-09-25 — is the `app.quit`
action on Windows and Linux, shortcut `Ctrl+Q`. It quits all windows in one
gesture, through `⌘Q`'s path. It calls a dedicated IPC command,
**`request_exit`** (`commands/recovery.rs`):

- **without an argument**, and without a return value other than the
  acknowledgment;
- it only calls the Rust function that `on_run_event` calls for `oxyn-quit`
  and `CloseRequested`: ADR-0043's resolution of open transactions, then the
  orderly shutdown of ADR-0021 and ADR-0038. It chooses nothing — no window,
  no delay, no skipped step — and therefore cannot request an exit that does
  not flush drafts or does not record the closing;
- it is idempotent: `begin_shutdown` only starts the shutdown once, and a call
  during a transaction resolution in progress does nothing;
- it emits no `Command`: it is not an action on data, but interface plumbing,
  like `subscribe_shutdown` and `shutdown_flushed`.

It is registered on all three platforms: on macOS, the palette calls it for
`app.quit`, the native bar keeping its item handled in Rust.

**Effect on the input surface** ([SECURITY](../SECURITY.md#input-surface),
point 5). An XSS gains a way to **request** the orderly exit — which closing
the window already does —, nothing more: drafts are flushed, the closing is
recorded, an open transaction opens ADR-0043's dialog instead of being
committed or rolled back silently. It reads nothing, writes nothing on a
server and crosses no confirmation. The worst is a denial of service: the
application closing, and reopening with its consoles.

Making the window undecorated (`decorations: false`, window controls drawn by
Oxyn) is **not** decided here: it would require additional `core:window:*`
permissions.

### 6. Context menus: web, from the registry

Each surface UX-SPEC lists ("Context menus") has a shadcn `context-menu` on
Base UI, whose entries are registry actions filtered by surface, with the
target in the `ActionContext`. The precedent is `catalog-tree.tsx`. Each
surface has its stories, axe included: that is what makes this choice
checkable, and that is what a native menu would lose.

### 7. Palette, quick open, shortcut sheet

- **`⌘K`**: the palette, on shadcn `command` (`cmdk`, already a dependency).
  It lists the registry's actions and calls `invoke(id, "palette")`. It
  complements the menu bar, it does not replace it.
- **`⌘P`**: quick open of an object, on the catalog's existing search
  (`search_catalog`), which only covers loaded objects and says so. `Ctrl+P`
  being WebView2's print, the dispatcher intercepts it.
- **`⌘/`** outside the editor: the shortcut sheet, **generated from the
  manifest** with `kbd`. No shortcut list is written by hand anywhere else,
  and the `kbd`s that today display a shortcut written next to its binding
  ("Context") read it from the manifest.

### 8. What would betray the webview

The behaviors are UX-SPEC's; the mechanisms are these.

- **Page context menu**: a `contextmenu` listener on `document` calls
  `preventDefault`, except on a native text field (`input`, `textarea`)
  without its own menu. The SQL editor has its own.
- **Reload**: `⌘R`, `⌘⇧R`, `Ctrl+R`, `F5` are reserved in the manifest as
  neutralized combinations; the dispatcher absorbs them. A reload destroys
  unsaved state, and orphans the tasks that fed the `Channel`s (header comment
  of `commands/subscriptions.rs`).
- **Page zoom**: `zoomHotkeysEnabled` stays `false`. Pinching is neutralized
  outside the `erd` diagram (point to check no. 5).
- **Back navigation**: swipe gestures are off by default; mouse buttons 4 and
  5 are absorbed (`mouseup`/`auxclick`); `⌘[` and `Alt+←` are only the named
  back actions UX-SPEC provides. As a last line of defense, `on_navigation` on
  the Rust side refuses any navigation outside the application's origin, and
  `on_new_window` any new window.
- **Text fields**: `spellcheck="false"`, `autocorrect="off"`,
  `autocapitalize="off"`, `autocomplete="off"`, on fields and on the
  CodeMirror surface (`contentAttributes`). `components/ui/` not being edited
  by hand, the attributes are set by the Oxyn components that use them, and a
  `make front` check refuses an `Input` or a `Textarea` that does not receive
  them. The risk targeted: macOS typographic quotes in a connection string or
  a SQL literal (point to check no. 4).
- **Selection**: `user-select: none` on the frame, `text` on the contents —
  it is already `styles.css` (`body`, then `input`, `textarea`, `.cm-editor`,
  `[data-selectable]`); this ADR fixes it.
- **External links**: no external `<a href>` is rendered in the webview. Oxyn
  opens its own links (documentation) through an `open_external` command,
  which only accepts `https:` and URLs Oxyn declares — never a URL read in a
  cell, a catalog comment or a model response, whose opening would exfiltrate
  what its query carries. `allowLinkPreview` becomes `false`.

### 9. What shadcn does not provide

**General rule: a system gesture — choosing a path, opening a link, revealing
a file, receiving a drop — runs in Rust, behind an Oxyn command that bounds
it.** No plugin permission is added to `capabilities/main.json` for them.
`dialog:allow-open`, already granted to the connection screen, is not reopened
here.

- **File dialogs**: `tauri-plugin-dialog`, called from Rust by the command
  that consumes the path (export, open a `.sql`). A write destination never
  comes from JavaScript.
- **System file drop**: `WindowEvent::DragDrop` handled in
  `crates/oxyn-desktop`, the paths classified (`.sql`, database file readable
  by a registered driver, other) and passed to the front end through a
  `Channel`. A `.sql` is read in Rust, on the blocking pool, with a size
  bound, and opened in a console without execution.
- **Internal drag and drop** (tabs, columns, catalog to editor): **on pointer
  events, not on the HTML5 API**, since the file drop keeps `dragDropEnabled`
  at `true` and that excludes HTML5 dragging on Windows ("Context", point 7).
  The choice of a library or an in-house implementation is deferred; a library
  will go through [`/versions`](../../.claude/commands/versions.md). Dropping a
  table in the editor inserts the name **quoted by the backend**, at the
  pointer position, without executing anything.

### 10. The invariants, action by action

- **[I-01](../../CLAUDE.md#i-01).** A menu is one more trigger. Every entry
  ends in `invoke`, which calls the same `lib/ipc/` functions as a button; the
  `Command` is born in the backend, as for any IPC call. The predefined native
  items only act on the system and the webview (a field's clipboard, window,
  application visibility), never on data.
- **[I-02](../../CLAUDE.md#i-02).** A `destructive` entry — `Drop…`,
  `Truncate…`, `Rename…`, `Delete…` — executes nothing: it opens ADR-0042's
  in-place review, whatever the trigger. It has no shortcut (point 3), and
  does not exist for an agent. No entry, no shortcut grants an approval on
  `production`: it goes through the native dialog of
  [ADR-0037](0037-dialogue-natif-pour-les-confirmations-critiques.md), which
  only the backend opens.
- **[I-03](../../CLAUDE.md#i-03).** `Copy connection` only copies what the
  front end already holds: a connection's parameters and secret reference
  never cross IPC ([ARCHITECTURE](../ARCHITECTURE.md), "The Tauri
  interface"), and **no command is added to produce a connection string to
  copy**. Every copy goes through `copyToClipboard`
  (`features/metadata/clipboard.ts`), which the clipboard channel's sentinel
  test covers.
- **[I-06](../../CLAUDE.md#i-06).** A column's `Copy values` copies the rows
  the result holds, read in bounded pages, within the `MAX_COPY_ROWS` limit
  (2,000, `components/oxyn/grid-selection.ts`); beyond, it refuses and points
  to `Export…`. It never reads the rest of the cursor and never reruns the
  query. The label says the number of rows.
- **[I-10](../../CLAUDE.md#i-10).** Any SQL an action composes —
  `Copy as ▸ Quoted name`, `SELECT *`, `INSERT template`, `Copy rows as ▸
  INSERT` or `IN list`, the name inserted by dragging — is produced **on the
  Rust side**, identifiers quoted and literals escaped by the driver, as
  `qualified_name` and `related_rows_template` already are. The front end has
  no SQL string template.
- **[I-07](../../CLAUDE.md#i-07).** No action takes a model's text as input to
  execute it. An assistant code block offers `Copy code` and
  `Open in console`; `Open in console` places text, and it is `Run`, in the
  console, that executes.
- **[I-04](../../CLAUDE.md#i-04).** `Send to assistant` only transmits values
  through a sample's approval screen, as UX-SPEC writes.

## Consequences

* **+** An action has one definition, hence one greying condition, one label
  and one shortcut: the button, the menu, the palette and the sheet can no
  longer diverge.
* **+** Shortcut conflicts become a test failure, instead of an action that
  does not fire.
* **+** No permission is added to the webview: what an XSS can do with the
  menus is limited to invoking actions a click already offers.
* **+** The native bar exists from startup and its labels depend on no
  JavaScript.
* **−** **Two menu bars**, native on macOS, web elsewhere, from one manifest.
  The native one cannot be tested in a story: only its construction and the
  refusal of an unknown `id` are tested, in Rust.
* **−** **A Rust crate reads a front-end file** (`include_str!` to
  `apps/desktop/src/lib/actions/actions.json`): a path coupling between the
  two toolchains, which breaks at the first move of the file.
* **−** **On macOS, the reason for a greying cannot be read in the bar**:
  `muda` has no tooltip. The palette shows it. It is a gap with UX-SPEC
  ("greyed out, with its reason, readable on hover"), reported rather than
  settled.
* **−** **On macOS, `Cancel` displays without `Esc`** in the native bar.
* **−** After a zone change, the native accelerator is moved by an IPC call: a
  keystroke arriving during this latency can target the previous zone's
  action. `invoke` re-evaluates `enabled`, but not the intent.
* **−** A keyboard dispatcher written by Oxyn, and its per-layout tests, to
  maintain instead of a library.
* **−** Two more IPC commands (`subscribe_menu`, `set_menu_state`), plus
  `request_exit`, `open_external` and the drop transmission: each is a surface
  to review as a security change ([SECURITY](../SECURITY.md#input-surface),
  point 5). These commands emit no `Command`: they are not actions, but
  interface plumbing, like `subscribe_events`.
* **−** Dragging on pointer events costs more code than the HTML5 API, and
  CodeMirror no longer receives a native drop there: the insertion position is
  computed (`posAtCoords`).
* **−** Plugin actions will need a dynamic section of the native bar; it is
  not designed here, only made possible by the reserved namespace and the
  required declarative nature.

**Exit cost:** abandoning the native bar for the web bar on macOS means
deleting `menu.rs` and two commands — a few days —, giving macOS back a
minimal menu that keeps ADR-0038's Quit: without it, `⌘Q` falls back on
`terminate:`. Abandoning the registry means scattering each action back into
its triggers: a cost that grows with the number of actions, bounded because
they all call the same `lib/ipc/` functions and the manifest holds their list.

**Reconsider if** one of the points to check below contradicts what is
decided; if tao handles `applicationShouldTerminate:` (Quit could become a
predefined role again, as ADR-0038 provides); if Tauri exposes
`AreBrowserAcceleratorKeysEnabled` (point 8 would be simplified); if the
undecorated window is decided on Windows and Linux (the web bar would join
the title bar there); if phase 4 plugins contribute actions; or if
customizable shortcuts are requested — the manifest would become a default
layer, and overrides a readable workspace file ([I-11](../../CLAUDE.md#i-11)).

## Points to check

Not checked against a source on 2026-09-25; none is written elsewhere as a
fact. The question of the `terminate:` path, open at the time of writing, is
settled by ADR-0038 and ADR-0040 ("Context", point 2).

1. **The delivery order under WKWebView** of a `⌘` keystroke between the page
   and the native bar, and whether `preventDefault` in the page prevents the
   menu item. The "single binding" rule of point 4 is designed not to depend
   on it. The answer matters today: it says whether `⌘W` closes the tab or
   quits Oxyn ("Context").
2. **That, without the predefined `Edit` items, `⌘C` and `⌘V` stop working in
   a webview field on macOS.** Commonly reported, not checked. The decision
   keeps these items anyway.
3. **That a registry action can undo the editing of a native `input`**
   (`document.execCommand("undo")` under WebKit), and that `undo:` reaches
   CodeMirror's history. Decides whether Undo and Redo are actions or roles
   (point 4).
4. **That `autocorrect="off"` turns off macOS typographic quotes and dashes
   in WKWebView**, which belong to the system text substitution setting.
5. **Pinching**: magnification disabled by default in WKWebView, and
   WebKitGTK's behavior.
6. **That `preventDefault` on `keydown` neutralizes WebView2's browser
   shortcuts** (`Ctrl+R`, `F5`, `Ctrl+P`), since Tauri does not expose their
   switch; and that `⇧F10` does not already emit `contextmenu` there, which
   would open the menu twice.
7. **Displaying a combination on the active layout** as UX-SPEC requires
   ("Keyboard"): `navigator.keyboard.getLayoutMap()` is not guaranteed outside
   Chromium, and macOS may itself relocalize the native bar's key
   equivalents. As long as this is not checked, a punctuation mark displays as
   its character (`⌘/`), not as the key to press (`⌘⇧:` on AZERTY).

## Rejected alternatives

| Alternative | Reason for rejection |
|---|---|
| JavaScript API `@tauri-apps/api/menu` | requires `menu:*` permissions, and `core:event` to listen to clicks, in `capabilities/main.json`: an XSS could create, rename or trigger menu items. That file's description explicitly rules out `menu` |
| Native menu on all three platforms | on Windows and Linux, it stacks under the system title bar, above Oxyn's header; it does not follow the theme; it cannot be tested in a story. The rendering under GTK is an assessment of 2026-09-25, not measured |
| Web bar on macOS too | a macOS user expects the global bar; Hide, Services, Window and the `Edit` roles live there, and an empty screen bar looks broken |
| Palette only, without a menu bar | an audience coming from DBeaver, SSMS or DataGrip discovers features and learns their shortcuts by browsing menus; a palette assumes knowing the name of what one looks for, and offers no navigable structure to screen readers |
| Native context menus (`muda`'s `popup`) | an IPC round trip per right click, with the target to describe to Rust; no story, no axe, no theme; and contextual entries change with each target, whereas the bar is stable |
| Menu described in Rust, next to the TypeScript registry | two declarations of the same labels and shortcuts, which diverge; it is the rule written in two places that the repository refuses |
| Menu described by the front end and sent to Rust at load | the bar only exists after the webview loads, and an XSS could rewrite its labels — renaming an entry to get another one clicked |
| `@tanstack/react-hotkeys` as dispatcher | declares itself alpha; its matching rules for AZERTY, `⌥` and non-Latin layouts are not checked; zone resolution is not its model |
| Let each component hold its shortcuts | it is the current state: four mechanisms, no place where a conflict shows, two defects already present |
| HTML5 dragging, `dragDropEnabled` at `false` | removes the system file drop on Windows, which UX-SPEC requires |
| In-memory history for the router | closes back navigation by construction, but changes the routing of the whole application for a defect that interception and `on_navigation` close; remains the answer if a back path escapes them |
| `Esc` as native accelerator of `Cancel` | captures `Esc` in the whole window during an execution: a dialog or a completion no longer closes, the query is cancelled instead |
