## Initial issues enriched

### [#7](https://github.com/so-keyldzn/oxyn/issues/7)

Confirmed by two synthetic network trials on the Oxyn libraries: 307 and 308 keep the POST, the prompt and a fake Anthropic key between two loopback ports. No remote recipient or real secret. The Local→remote egress remains a consequence of the redirect path and of the absence of a new Reach check, not an actual transfer performed. Sources: [RFC 9110, 307](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4.8) and [reqwest v0.13.4, policy and header removal](https://github.com/seanmonstar/reqwest/blob/v0.13.4/src/redirect.rs).

### [#8](https://github.com/so-keyldzn/oxyn/issues/8)

Confirmed by execution: the OpenAI-compatible and Anthropic decoders return `ChatEvent::Error` containing the sentinel key of the simulated provider. No real secret. The [Anthropic streaming error events](https://platform.claude.com/docs/en/build-with-claude/streaming#error-events) document this channel after the stream opens. This source establishes the protocol; the leak is established by the Oxyn test. No disk leak demonstrated.

### [#9](https://github.com/so-keyldzn/oxyn/issues/9)

The [React documentation on captured state](https://react.dev/learn/state-as-a-snapshot#state-over-time) explains why the continuation keeps its old `current` after `setClosing(null)`. The earlier React reproduction remains the evidence of the Oxyn defect. Limit maintained: the store refuses to close a modified document without discarding; no loss of later changes was demonstrated.

### [#10](https://github.com/so-keyldzn/oxyn/issues/10)

[React useRef](https://react.dev/reference/react/useRef#reference) confirms the persistence of the mutable reference; [Tauri, command return and errors](https://v2.tauri.app/develop/calling-rust/#returning-data) describes the acknowledgement by resolution/rejection of the Promise. In Oxyn, `lastDraft` advances before this acknowledgement. The two earlier reproductions remain valid: new seed not written, and flush after failure without a new write.

### [#11](https://github.com/so-keyldzn/oxyn/issues/11)

[PostgreSQL 18, volatility](https://www.postgresql.org/docs/18/xfunc-volatility.html) confirms that a VOLATILE function can modify the database; [READ ONLY mode](https://www.postgresql.org/docs/18/sql-set-transaction.html) documents the protection of non-temporary tables. PostgreSQL 18 is the documentation version consulted, not a detected server. Installed client: SQLx 0.9.0. Still no PostgreSQL reproduction: static finding. Nuance for the fix: READ ONLY is not a general containment of side effects, and notably has exceptions on temporary tables.

### [#12](https://github.com/so-keyldzn/oxyn/issues/12)

Local network reproduction run on the real provider: cancellation set at 40 ms, operation still pending at 250 ms, returning only when the server closes at 547 ms. Synthetic body and server. The diagnostic is therefore indeed awaited outside the cancellation select. [reqwest, Response::text](https://docs.rs/reqwest/0.13.4/reqwest/struct.Response.html#method.text) documents reading the body; Oxyn's 512-byte limit applies afterwards.

### [#13](https://github.com/so-keyldzn/oxyn/issues/13)

Bounded reproduction run: 128 frames whose argument data are 131,072 bytes each produce a final argument of 16,777,216 bytes. No OOM caused. This demonstrates that the per-frame cap is not a cumulative cap; the absence of a total bound is established in the concatenations. The [Anthropic tool delta documentation](https://platform.claude.com/docs/en/build-with-claude/streaming#input-json-delta) describes this protocol accumulation without guaranteeing a client budget.

## Details of the new findings

### [#23 — Preserve the existing file when an export is cancelled or fails](https://github.com/so-keyldzn/oxyn/issues/23)

#### Problem

File::create truncates the destination before the export tests for cancellation. An export whose token is already cancelled can therefore destroy the previous file and then return an error.

#### Scenario

Create a synthetic result, write a non-empty temporary file, cancel the token before a CSV Command::Export targeting this file, compare its content after the error.

#### Evidence and limits

Reproduction run via the real Executor::dispatch, temporary SQLite and a sentinel file `EXISTING USER DOCUMENT`: `cancelled export error=Some("operation cancelled")`, `previous_file_len=0`. No user file touched. The code already checks unsupported formats before File::create, but not cancellation nor all later failures.

#### Contract

Preservation of the user's work; common Export command, I-01; the export contract does not justify silently destroying previous content.

#### Locations

- [crates/oxyn-exec/src/executor.rs:986](https://github.com/so-keyldzn/oxyn/blob/c19e7f61327bf70903079e053f47f7e03c043bad/crates/oxyn-exec/src/executor.rs#L986-L995)
- [crates/oxyn-data/src/export.rs:230](https://github.com/so-keyldzn/oxyn/blob/c19e7f61327bf70903079e053f47f7e03c043bad/crates/oxyn-data/src/export.rs#L230-L235)

#### Official sources consulted on September 24, 2026

- [Rust 1.98.1 — File::create](https://doc.rust-lang.org/std/fs/struct.File.html#method.create) — Creating for writing immediately truncates an existing file.

The sources establish the external contracts; the evidence above establishes their application in Oxyn.

#### Acceptance criteria

- [ ] Write to a temporary file in the same directory, then replace only after complete success.
- [ ] Preserve the previous bytes on prior/ongoing cancellation or on a read/encoding error.
- [ ] Clean up the temporary file and test the nominal export.

After the fix: targeted verification then `make qualite`. No product fix in this audit.

### [#25 — Decide how old abnormal shutdowns are acknowledged to avoid a permanent recovery](https://github.com/so-keyldzn/oxyn/issues/25)

#### Problem

An old abandoned session stays counted at every launch. Cleanly closing a later session does not acknowledge it; the cleanup only deletes closed sessions. The screen can therefore keep announcing an abnormal shutdown after every clean close.

#### Scenario

Synthetic crash -> launch and recovery -> clean close -> new launch. Observed result: after_crash=Abnormal, after_clean_close=Abnormal.

#### Evidence and limits

Reproduction on a migrated temporary Store: first session with an artificially aged heartbeat; second session observes Abnormal, then closes cleanly; third still observes Abnormal. No acknowledgement in the module's methods. **Explicit internal divergence:** the code literally follows ADR-0021 (any old abandoned session), while UX-SPEC promises no recovery after an ordinary close. Do not silently fix one against the other.

#### Contract

docs/UX-SPEC.md:137-140 against the wording of ADR-0021:52-55. The acknowledgement decision belongs to the product; a library documentation does not settle it.

### [#29 — Do not record a clean shutdown without the front end acknowledging its drafts](https://github.com/so-keyldzn/oxyn/issues/29)

#### Problem

shutdown ignores the expiry of the FlushDrafts wait, then still calls close_session_after_local_writes. If no work has reached the backend, pending==0 and closed_at can be written without the front end having confirmed the submission of its drafts.

#### Scenario

Front end not answering FlushDrafts during the two-second grace period; no write submitted yet. The application must be able to exit, but must not claim to have confirmed a clean shutdown.

#### Evidence and limits

Independent second reading and targeted reproduction: shutdown method extracted exactly from the file, real Tokio, simulated channel and persistence. With no acknowledgement at all: `flush_acknowledged=false clean_close_requested=true elapsed_ms=2017`.
