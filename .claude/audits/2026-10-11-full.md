## Refuted

**R1 (security and AI, proposed P2)** — "External-agent env names holding
AWS-style credentials (`AWS_SECRET_ACCESS_KEY`, `*_ACCESS_KEY`) are stored in
clear unless the user ticks 'secret'." The code path is real
(`agent_env_is_secret` at `crates/oxyn-core/src/ai.rs:734-743` does not match
it), but `docs/SECURITY.md:56-64` specifies exactly this enumerated rule and
"The user can mark any other variable secret. Other values stay in clear." The
form shows a `Secret: <NAME>` switch per variable with a notice asking to mark
other sensitive variables (`provider-form.tsx:446-474`), and a ticked name goes
to the keychain and is masked. Not published as a defect; widening the name
heuristic remains a hardening suggestion for the maintainer.
